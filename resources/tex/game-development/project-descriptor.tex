	Concepts}.

	\section*{Authenticity}
	All parts of your submitted assessment \textbf{must} be completely your work. Do your best to complete this assessment without using  AI tools. You need to demonstrate to the course lecturer that you can meet the learning outcomes for this assessment. \\
	
	Learning to use AI tools is an important skill. While AI tools are powerful, you \textbf{must} be aware of the following:

	\begin{itemize}
		\item If you provide an AI tool with a prompt that is not refined enough, it may generate a not-so-useful response
		\item Do not trust the AI tool's responses blindly. You \textbf{must} still use your judgement and may need to do additional research to determine if the response is correct
		\item Acknowledge what AI tool you have used. In the assessment's repository \textbf{README.md} file, please include what prompt(s) you provided to the AI tool and how you used the response(s) to help you with your work
	\end{itemize}

	It also applies to code snippets retrieved from \textbf{StackOverflow} and \textbf{GitHub}. \\
	
	Failure to do this may result in a mark of \textbf{zero} for this assessment.

	\subsection*{Functionality - Learning Outcomes 1, 2 (25\%)}

	\textbf{Note:} If you wish to develop different games than those specified below, you \textbf{must} get approval from the course lecturer first.

	\begin{itemize}
		 \item  \textbf{Godot 2D Platformer} game with the following functionality:
		 \begin{itemize}
			\item Player movement using keyboard input.
			\item Platform collision system, i.e., solid, moving and one-way platforms.
			\item Health system.
			\item Win and lose conditions.
			\item Three distinct levels with increasing difficulty.
			\item Hazards and obstacles, i.e., spikes, traps or pits.
			\item Three distinct enemies with different behaviours.
			\item Double jump ability.
			\item Collectible items, i.e., coins or power-ups.
			\item Scoring system.
			\item Choose five features of your choice. These features should be different from the ones listed above.
		 \end{itemize}

		 \item \textbf{3D Unity/Godot Obstacle Dodging} game with the following functionality:
		 \begin{itemize}
			\item Player movement using keyboard or mouse input.
			\item Obstacle collision system, i.e., solid and moving obstacles.
			\item Health system.
			\item Five distinct obstacles with different behaviours.
			\item Two distinct levels with increasing difficulty.
			\item Collectible items, i.e., coins or power-ups.
			\item Scoring system.
			\item Camera effects, i.e., screen shake.
			\item Choose five features of your choice. These features should be different from the ones listed above.
		 \end{itemize}

		 \item Deploy both games to \textbf{Itch.io}.
	\end{itemize}
	
	\subsection*{Code Quality and Best Practices - Learning Outcomes 1, 2 (40\%)}
	\begin{itemize}
		\item Write clean, readable, and maintainable code.
		\item Use modular, reusable components and avoid code duplication.
		\item Keep code simple and easy to understand.
		\item Optimise performance by managing resources efficiently.
	\end{itemize}
	
	\subsection*{Version Control - Learning Outcome 1 (5\%)}
	\begin{itemize}
	  \item Regular commits are made throughout development, demonstrating meaningful progress.
	  \item Commit messages are clear and descriptive.
	  \item The repository shows a clean and logical commit history that reflects the development process of the games.
	\end{itemize}
